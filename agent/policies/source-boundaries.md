# Source boundaries

AgentLab can study public agent systems, but it should not turn unsafe or
unauthorized material into project assets.

## Allowed

- Official documentation, release notes, public repositories, package registries,
  and official blog posts.
- Reproducible local observations from public packages or public source code.
- News, security reports, papers, and public analysis articles when clearly
  marked as secondary sources.
- Metadata about a leak event, such as timeline, public statements, and supply
  chain lessons.

## Not allowed

- Private prompts, private account exports, credentials, tokens, internal logs,
  or customer data.
- Unauthorized leaked source code, source maps, debug bundles, or mirrors as
  project inputs.
- Long verbatim excerpts from copyrighted sources.
- Treating third-party claims based on leaked material as direct AgentLab facts.

## Required labeling

- `official fact`: directly supported by official docs or official packages.
- `primary observation`: reproduced locally from public material.
- `third-party claim`: reported by another author and not reproduced here.
- `AgentLab inference`: a design conclusion drawn from sources.
