Sub-agent 编排

已核验

主 Agent 将边界清晰的工作交给独立执行上下文，并负责等待、协调与汇总结果的机制。

观察对象
Claude Code · Codex · opencode
证据层
Runtime Prompt · Tools
核验日期
2026-08-08
01

机制边界

这里观察的是任务如何被拆出、执行和收回，不评价底层模型能力。

1识别边界找到可独立推进的任务
2创建执行者注入目标与必要上下文
3独立执行运行并保留自己的状态
4回收结果等待、追问或中断后汇总
02

实现对照

三者都支持委派，但暴露给主 Agent 的控制面明显不同。

Agent 派发入口 协调方式 状态模型
Claude Code Agent 工具与 agent type SendMessage、后台通知、任务控制 独立上下文，可选择 worktree 隔离
Codex spawn_agent 创建 Agent 树 消息、追问、等待、中断均为独立工具 共享工作区，按 Agent ID 保留会话
opencode task 工具与 subagent type 后台完成通知，结果由主 Agent 转述 默认新上下文，以 task ID 恢复会话
03

观察结论

以下是基于可见接口的工程观察，不等同于厂商声明。

01

控制面的颗粒度不同。 Codex 将 Agent 生命周期拆成多项协作工具；Claude Code 和 opencode 更强调单一派发入口。

02

隔离不只等于独立对话。 Claude Code 明确暴露 worktree 选项，Codex 的可见约束则强调共享文件系统。

03

恢复语义正在成为标准能力。 三者都提供某种形式的持续沟通或上下文复用，而不只返回一次性结果。

04
