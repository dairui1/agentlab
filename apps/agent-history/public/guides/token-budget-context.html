04

沿版本地图读源码，不把类比当实现

主动换窗、compaction 接到换窗、notes/history 扩展，并不是同时发布的。

主动 new_context_window 从 0.140.0 随稳定版分发；手动和自动 compact 的 TokenBudget 路径从 0.143.0 开始；history-notes 扩展从 0.150.0 开始。

固定 0.151.0 默认关闭 TokenBudget。当前窗口、checkpoint 和历史库很像工作内存与存储的分工，但实现不是操作系统虚拟内存，没有自动页面置换的同等保证。

原研究保留版本源码、引用位置与已有证据。真实任务连续性仍取决于交接质量、检索行为和验收，不能只由一张三层图保证。

这套设计改变的是记忆的分工：当前对话不再必须承担全部任务连续性。

换窗不难，难的是留下足够好的交接，并能在需要时准确回到原文。

没有自动全知的笔记，也没有只因 history 存在就不再丢约束的保证。

原文、源码与核验记录

研究固定 Codex 0.140.0–0.151.0；0.151.0 的 TokenBudget 仍是 UnderDevelopment、默认关闭。。教学场景解释固定功能分支，不修改真实会话，不设虚构窗口容量，也不保证笔记完整。

TB-01 · 模型主动换窗从 0.140.0 开始随稳定版发布

rust-v0.139.0 还没有 new_context_window handler，rust-v0.140.0 已包含它；工具返回的固定消息明确说，新 context window 会在不总结 conversation history 的情况下启动。

这证明能力进入 0.140.0 源码，不证明 feature 在普通用户配置中默认开启，也不证明每次换窗都由模型主动触发。

TB-04 · 名字与客户端生命周期被刻意保留

TokenBudget 路径仍运行 PreCompact/PostCompact hooks，并发出 ContextCompaction item 的 started/completed 事件；因此客户端看到的仍是 compaction，replacement 内核却已经换成新窗口。

公开 item 类型无法单独告诉客户端内部究竟用了 summary 还是 hard reset；需要结合 feature/provider 配置或 trace 判断。

TB-06 · notes 是可写工作集，history 是只读恢复面

0.151.0 的工具合同把 notes 定义为可跨 context-window transition 生存的私有文件，并提供 list/read/search/append/write；history 只提供 list windows、list items、read item 与 search contents，而且明确只读、最终一致。

notes 仍是模型维护的有损工作笔记；history 可查询不等于旧内容持续占据当前 attention，也不等于所有旧状态都能被自动找回。

TB-07 · 精确回读靠 window_id + item_id

history.read_item 要求同时传入 window_id 与 item_id；list/search 可按 window、role、tool namespace 和 tool name 过滤。因此 checkpoint 里保留关键引用，比只写一段模糊摘要更利于定点恢复。

记录 ID 是检索指针，不是语义记忆；模型仍需先知道该找什么，或通过 list/search 进行有限查询。

TB-09 · 模型会拿到窗口身份与剩余 token

TokenBudget context 给模型注入 agent name、first/current/previous window ID，并单独报告当前窗口剩余 token；这让模型可以在预算耗尽前写 checkpoint，而不是只能等 runtime 事后压缩。

看见剩余预算只提供了控制信号，不保证模型一定及时或正确地写 notes，也不保证 checkpoint 覆盖所有用户约束。

TB-10 · 它把上下文从唯一记忆降成可替换工作集

把窗口预算、主动 rollover、可写 notes 与只读 history 放在一起看，TokenBudget 的核心不是更好的 summary，而是让当前 prompt 变成可替换工作集：任务连续性由 checkpoint 与可寻址历史共同承担。

RAM、checkpoint、cold storage 只是帮助理解的系统类比；实现仍是模型请求、rollout 持久化和后端工具，不是操作系统虚拟内存，也没有自动页面置换的同等保证。
