昨晚的对话还在，昨晚的进程和文件却未必还在。

正常分支假定记录已写入且可读。沿保存、旧进程退出、新进程续接走一遍，再切换成仅内存的 ephemeral thread。

02

先说清楚，你想把什么找回来

恢复对话，不等于把昨晚那台运行中的机器按原样搬回来。

对话记录可以保存，但 background process、MCP socket、启动参数和文件状态各有自己的生命周期。读到旧历史后，宿主仍要重建运行环境。

文件回退也是单独的能力。回退对话中的一句话，不会撤销 Bash 已经发出的邮件、改动的外部文件或提交的数据库事务。

‘还记得’和‘还在运行’不是同一件事。

05

恢复之后，先对一下现场

对话回来只是第一步。

核对会话 ID、当前目录、代码 revision、模型、权限和连接状态。权限恢复在 Claude 固定构建与 live docs 间有路径相关冲突，安全接入应显式传入期望 mode 并核验。

需要回退文件时，先看 snapshot 覆盖。conversation rewind、file rewind 与外部副作用是不同合同；成功提示不能覆盖没有被记录的改动。

先确认恢复了谁，再确认它现在能做什么。

Session 是可继续的对话身份，不是整个运行环境的时间机器。

实际接入时，把身份、执行终态、持久记录和文件回读放在不同字段，缺哪份就明说哪份未知。

固定版本 Session 证据完整核验记录全部证据与待验证问题

SES-CC-01 · session_id 是机器寻址键，标题不是

新 session 使用 UUID；system/init 与每个 ResultMessage 都携 session_id。显式 name 可作为人类 resume handle，但自动标题不是稳定寻址键。

Harness 应先持久化 UUID 再渲染标题；不能用 AI title 作为 resume/fork foreign key。

SES-CC-04 · continue 是 cwd-latest resolver，resume 是 identity lookup

--continue/continue:true 选择当前 working directory 最近持久 session；--resume/resume 选择显式 ID 或 name。2.1.223 起跨 project 重名副本会拒绝歧义选择。

多租户或并发 Harness 不应使用 continue；必须保存显式 ID 与 resolver receipt。

SES-CC-05 · resume 恢复 conversation，不恢复旧进程

resume hydrate 已保存 message/tool chain；background process、MCP socket、launch-only flags、部分目录与当前 filesystem 状态不会被 transcript 自动恢复。

conversation continuity 不能证明 runtime、authority、plugin/MCP 或 workspace 等价；host 要重建并 diff manifest。

SES-CX-02 · ephemeral 是真正 in-memory thread

ephemeral thread 跳过 LiveThread 与 state DB persistence，path=null；可在 loaded list 出现，却没有 cold resume、archive、rollback 或跨进程发现介质。

ephemeral 不只是列表隐藏；进程退出后 conversation identity 也无法从 local store 恢复。

SES-CX-07 · turn/completed 是 live terminal，不是 durability receipt

turn terminal 状态为 completed/interrupted/failed；persistence append 出错只记录日志，随后 turn/completed 仍可发送。

用它结束 runtime spinner 是正确的，但声明已落盘必须有 readback 或 host durability receipt。

SES-CX-08 · stored、loaded、read 与 resume 是四个 surface

thread/list 列 stored；thread/loaded/list 列 resident；thread/read/turns/items 被动 hydrate；thread/resume 取得 live append ownership。notLoaded 是正常状态。

turns=[] 或 notLoaded 不代表没有 history；多数 API 会有意省略或分页 items。

SES-CX-11 · resume 是 snapshot + tail，不是历史通知 replay

resume 先返回 thread snapshot/page，再补 token/goal snapshot与仍 pending requests；过去 item/delta/warning/terminal notifications 不会完整重发。

客户端要 snapshot/page hydrate 历史，再接 live tail；不能用 notification reducer 重建全部过去。
