模型路由与回退

你选了一个模型，重试之后，究竟是谁在回答？

你在本次 turn 指定模型，Agent 解析有效配置、按对应能力组织请求，再把结果交回对话。下一次 turn 也可能继承这个选择。

教学场景，不连接真实 Agent、模型或外部工具。

02

模型名字只是开始

同一个名字，还需要配得上当前的能力资料。

工具 schema、输入类型、上下文窗口和 reasoning effort 都与目标模型有关。换名字之后继续沿用旧能力，可能连请求形状都不再合适。

最后一条回复的模型也不是完整成本账本。重试、子助手和辅助请求可能各有一次请求与用量；缺少这些回执时，费用应标未知。

记录每次请求的实际路由，不从最后一句回复倒推。

06

看见最终答案之前，先保留路由账本

失败尝试也属于这次任务。

每次请求记录模型、provider、用途、effort、能力快照和重试原因。换模型、换资料、换通道都留一条明确变更。

费用只在有真实 usage 或账单时填写。副作用发生后断流，是否重复执行在既有资料中仍有未知，不能因为相同 call ID 就默认安全重试。

最终模型不是这次任务的全部经历。

路由的要点不是选个更聪明的名字，而是知道每次请求实际用了谁，以及变化发生在哪里。

模型效果、最坏请求数和账单完整性，仍要真实请求与故障实验来回答。

MR-OC-14 · Retry schedule 没有 max attempt 分支

SessionRetry.policy 对 retryable error 返回下一次 Duration，没有按 attempt 终止的内建条件。

这不等于每个请求必然无限运行；取消或 non-retryable error 仍会终止。

MR-OC-15 · 整个 stream effect 在同一 input.model 上重试

SessionProcessor 对 llm.stream(streamInput) 应用 SessionRetry.policy，并发布 attempt/message/action/next；policy 使用 input.model.providerID，没有跨模型切换。
