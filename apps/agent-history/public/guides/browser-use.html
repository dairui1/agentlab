04

回到实现图，把客户端和后端分开

IAB 与 Chrome 共享客户端，不等于两边全部执行链都一样。

客户端有 API 裁剪、安全检查、framed JSON-RPC 和 response metadata。IAB 使用 App WebView；Chrome 另有扩展与 Native Messaging 连接。原研究保留对应构建文件和哈希。

只读 evaluate 使用 isolated world、DOM wrapper 与有界序列化。它是认真收窄页面 JavaScript 的设计，不是形式化的不可逃逸证明。

site-status 的请求或解析失败有局部 fail-open 分支；这不能扩大成整套策略 fail-open。原图、各层来源和剩余验证问题留在独立来源层。

一次浏览器任务要分别确认实例、目标、授权和结果；共享 API 不把这些边界抹平。

好的浏览器操作不是一直点到没报错，而是让当前页面、目标依据、用户意图和完成证据相互对得上。

接口存在只说明一种能力可表达；实际后端、权限和页面结果还要由当前状态回答。

BU-04 · Chrome 与 Browser 共享逐字节相同客户端

Chrome 插件内 browser-client.mjs 的完整 SHA-256 与 Browser 插件完全相同，因此两个入口共享这份客户端执行与策略代码，而不是维护两套 facade。

客户端相同不表示 IAB、Chrome extension 与 cloud CDP 的服务端实现相同；后端 capability 会改变暴露面。
