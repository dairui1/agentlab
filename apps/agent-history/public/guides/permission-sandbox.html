02

看得见工具，也可能用不了

目录里有一个工具，不代表这次调用已经获准。

工具可见性、规则决策、人类审批和 OS enforcement 是不同层。把它们压成一个绿色‘允许’，出错时就不知道卡在哪道门。

批准也不是执行完成。需要等工具终态，再检查文件或外部对象的结果；取消批准不能自动撤销已经发生的副作用。

先定位哪一层的允许，再讨论它允许了什么。

05

最后留下的，应当是决策来源

‘拒绝’至少要知道是谁拒绝的。

规则 deny、用户 reject、自动审查超时和 turn cancel 并非同一终态。保留原始 decision 和有效权限配置，别统一变成‘用户不允许’。

还有些边界藏在 hook 和 plugin 中：Claude HTTP hook 的网络失败默认非阻断；opencode plugin 若不主动 ctx.ask，granular rule 也未必在执行前生效。这些要按具体路径核验。

权限系统是否安全，要看每条实际执行路径，不看一个模式名。

批准回答‘可以试这一步吗’，执行边界回答‘这一步最多能碰到什么’。

这里没有验证安全隔离。跨平台、远程环境和插件执行都需要真实 conformance 测试。

PERM-CC-01 · 权限决策按阶段短路，不是规则投票

PreToolUse 先运行；声明式规则按 deny、ask、allow 分层解析，再由 mode 与 canUseTool 处理尚未决议的调用。后面的 allow 不能救回前面的 deny。

Harness 必须保留 winning stage 和 rule provenance；只记录最终布尔值无法解释为何 canUseTool 没被调用。

PERM-CC-03 · 六种 mode 是基线，不是相同强度的开关

default、acceptEdits、plan、auto、dontAsk 与 bypassPermissions 对未决调用分别执行提示、静态批准、分类、拒绝或近乎自动运行；显式 deny、ask、hooks 与安全 breaker 仍可能覆盖。

bypassPermissions 应描述为跳过大多数提示，而不是不可拦截；auto 还依赖服务端分类器。

PERM-CC-06 · canUseTool 只是最后一公里 dialog adapter

SDK callback 仅处理此前尚未被 hook、rule 或 mode 决议的调用；bypass、bare allow 与 dontAsk 都可让它完全不运行。

不能把 callback 当 invariant enforcement；需要看见所有尝试时应使用 PreToolUse 或进程外隔离。

PERM-CC-07 · headless 审批必须由 host 完成往返

claude -p 无法打开普通人类对话框；需要 PermissionRequest、SDK canUseTool 或 permission prompt tool 承接，否则需要提示的动作被拒绝或 run 中止。

非 TTY 模式会跳过 workspace trust UI，2.1.226 还可能静默忽略无效 settings；host 必须自行校验。

PERM-CC-09 · Bash sandbox 与 permission 是两层

OS sandbox 只包住 Bash 及其子进程，不包含内建 Read/Edit/Write、MCP、hooks 或 computer use；macOS 用 Seatbelt，Linux/WSL2 用 bubblewrap，native Windows 不支持该 Bash sandbox。

native Windows Harness 不能宣称获得同一 containment；其他平台初始化失败也默认警告后无沙箱执行，只有 failIfUnavailable=true 才会启动失败。

PERM-CX-01 · approval policy 与 runtime sandbox 是正交轴

approvalPolicy 决定是否需要 host 决策，sandboxPolicy 决定已获准动作的实际执行边界；同一 approval policy 可配不同 sandbox。

批准不代表无沙箱执行，沙箱拒绝也不等于用户拒绝。

PERM-CX-06 · 单命令 sandbox override 有三态

tool call 可选择 use_default、require_escalated 或 with_additional_permissions；额外 permissions、justification 与 prefix_rule 属于该次调用提案。

单次 override 不会自动改写 thread 基线；persistent prefix 仍需 host 明确选择。

PERM-CX-10 · approval resolution 不是 execution completion

PERM-OC-02 · 多 pattern request 中 deny 会在 asked 前短路

每个 pattern 分别求值；任一个 deny 立即抛 PermissionDeniedError，不进入 pending，也不发 permission.asked。只有至少一项 ask 且没有 deny 才暂停。

没有 asked 既可能是全 allow，也可能是 policy deny；一个 request 不支持逐 pattern 批准。

PERM-OC-05 · 外部文件通常经过 external_directory 与 read/edit 两道门

boundary 外目标先请求 external_directory，再按实际动作请求 read 或 edit；允许越界不自动允许读取或修改。

PERM-OC-07 · permission 是应用 gate，不是 OS sandbox

外部路径扫描仅覆盖有限静态命令与参数；通过 admission 后直接以完整 process.env 启动宿主 shell，没有在该执行点装配 seccomp、container 或 Seatbelt。
