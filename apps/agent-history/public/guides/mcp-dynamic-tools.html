04

dynamicTools 为什么不是另一种 MCP？

Codex 把一组宿主工具定义注册在 thread/start，调用时反向请求 host。

这条路径没有 MCP transport、initialize、OAuth 或远端 catalog。dynamic specs 会持久化到 thread，恢复时可从历史读取；真正执行仍由 host handler 接住 item/tool/call。

固定 handler 没有独立 wall-clock timeout。接入方仍须定义截止时间、取消与结果回执，不能从‘注册成功’推出 handler 永远可用。

定义工具与提供执行器，是两份工作。

05

把连接状态和工具身份带到下一步

每一层都要保留自己的名字。

记录 server 配置来源、当前 status、catalog revision、raw route 和本次结果。缓存、直接宿主 API 与模型调用分别标出，别共用一个‘已连接’灯。

MCP server 自己的重试、事务与幂等能力仍要查 server-specific 合同。readOnlyHint 是声明，不是实际无副作用的证明。

连接好一个服务，还要接好它的状态。

MCP 把工具放到外部服务；dynamicTools 把执行请求交回宿主。两条路径先分清，再各自跟到结果。

服务就绪、目录可见和调用获准相互配合，但不能互相替代。
