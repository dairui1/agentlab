发布完成需要回执；回复新鲜度与有没有发出去是两个检查。

查看依据

send_later 的描述说投递可跨 container restart；Session 章节则说上下文和一次性 check-in 不跨 Session 清理或替换。这两个事件不是一个层级。

后继 Session 依靠 Thread、channel memory 和已交付产物恢复工作。持续任务要把承诺、在途工作和剩余项写到可读状态里。

持续工作不是同一段上下文永远不灭，而是每次醒来都能重新核对承诺和现实。

这份设计把请求来源、执行工具、通知节奏和恢复材料拆成可观察的合同。最值得借鉴的是把“答应了”与“真正送达、真正完成”分开。

claim 仍是建议性协调，服务器不保存 claim database；不能把目标“尽量只答一次”升级成 exactly-once。完整 85 项主工具索引与合同差异保留在原始证据层。
