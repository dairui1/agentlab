你让 Agent 打开一个已经登录的网站，再找到“下载报表”。它首先要找对浏览器：换一个没有登录的窗口，后面的点击再准确也没用。找到页面以后，它还要决定按按钮名称定位，还是看截图点坐标。点完，最后才是检查报表有没有出现。

这三个决定把 Browser Use 拆成了不同的职责。本文依据固定发行包解释这些职责，不是一段真实下载任务的运行记录。

01 / 整体模型

整体模型：先选浏览器，再决定怎样操作

先分清两个问题。“在哪儿操作”决定登录态和标签页，“怎么操作”决定如何定位目标。内置浏览器 IAB、扩展连接和 CDP 是三种浏览器接入方式；页面工具、按名称找元素、按节点编号操作和坐标点击，则是四种动作接口。它们不是同一张分类表。

产品合同把 Browser 作为内置浏览器的首选入口；依赖用户现有登录态、Cookie、扩展或已开标签页时，才用 Chrome 入口。两个插件装载的 browser-client.mjs 逐字节相同：入口不同，客户端共享。

共享客户端会根据已连接浏览器报告的能力，隐藏不支持的 API。因此，看不到某个方法不一定是故障；也可能是这个后端根本不提供它。标签页、内容导出、剪贴板和开发者检查等接口，同样受这层选择影响。

先保住正确的浏览器身份，再尽量用能说明目标的接口操作。基于已安装 26.730.61639 构建

这不意味着系统会自动从页面工具一路退到坐标点击。固定文件确认四种接口存在，也要求优先使用更明确的接口；真实任务怎样选择、失败后是否换路，还需要运行记录。

02 / 后端路由

后端路由：登录态属于哪个浏览器

需要网站上的已有登录态时，不能随便新开另一个浏览器。IAB 是 Codex 自己持有的 WebView；extension 连接用户已有的 Chrome 或 Edge；CDP 则通过调试协议连接受控实例。三者的页面和身份不应混用。

客户端提供直接选择 get()，以及按默认规则或 URL 选择的 getDefault()、getForUrl()。只有需要比较实例时才列出 list()，不必每次先做一次全量发现。选好浏览器之后，还要单独取得标签页的控制权；浏览器连接仍在，不代表旧标签页也仍由这次会话控制。

03 / 动作接口

动作接口：按按钮名称，还是按截图坐标

同样是下载报表，可以有不同的表达方式：调用页面声明的“下载”工具；找到名为“下载报表”的按钮；从可见节点里选一个编号；或在截图的某个位置点击。前两种保留更多目标含义，最后一种只告诉浏览器一个位置。页面移动以后，坐标不会替调用者认出原来的按钮。

固定客户端把这些方式放在同一个标签页对象上，名称分别是 WebMCP、Playwright、DOM-CUA 和坐标 CUA。下表解释它们各自依赖什么，不表示它们会按顺序自动尝试。

LAYER 1 · PAGE-DECLARED TOOL

页面直接声明可调用能力

页面可以公开结构化工具，Browser 通知会列出其名称与 schema。调用保留输入、输出和来源 hostname 的元数据，语义最强，但信任问题也最尖锐：页面内容不能因为“长得像工具”就获得用户授权。

04 / 只读执行

只读执行：evaluate 如何限制页面 JavaScript

有时只需检查页面状态，不必点击。playwright.evaluate 为这种观察提供了一条受限的 JavaScript 路径：它不直接在页面主执行环境里 eval，而是创建单独的 browser-use-readonly-js 环境。DOM 对象经只读代理暴露，一组基础对象被固定或替换，返回值也有深度、大小和类型限制。

model function
    ↓ serialize + validate
CDP isolated world: browser-use-readonly-js
    ↓ readonly DOM proxy / frozen intrinsics
page observation
    ↓ bounded serialization
JSON-compatible result

这不是安全证明。编译后代码能显示防护策略、被代理的对象和拒绝路径，却不能替代逃逸测试。尤其要验证 getter、副作用 API、跨 realm prototype、iframe、导航中断和非 JSON 对象等边缘情形。把它称为“只读页面沙箱”比“任意页面 JS”准确，也比“绝对无副作用”诚实。

为什么这件事值得单独核对？观察调用通常不需要像提交表单那样确认。若只读边界被绕过，原本只是“看看”的代码也可能产生动作。所以这里既关系到检查效率，也关系到授权。

05 / 信任边界

信任边界：模型代理、Security Gate 与本地协议

模型写下 JavaScript，并不等于它拿到了所有宿主权限。初始化函数 setupBrowserRuntime() 要求宿主提供受信的 Node REPL 桥。模型看到的 agent.browsers 是裁剪后的代理；真正执行时，受信客户端先把方法转换为命令，检查是否允许，再交给浏览器后端。

本地通道使用 4-byte length framing 的 JSON-RPC，并存在单独的 `browser-use-peer-authorization.node`。静态符号与依赖显示它读取 audit token、代码签名和进程身份来判断 socket 对端，而不是只相信“能连上路径”的客户端。

这条边界解释了为何普通脚本不能简单复刻 Browser Use：API 的 JavaScript 外观只是最上层。真正的 browser registry、native pipe、对端授权、用户确认和 response metadata 都由宿主 bridge 提供。

06 / 宿主结构

宿主结构：IAB 的可见 WebView 与隐藏 Host

Codex 的 `app.asar` 不只留下一个 WebView 组件。发行包中可观察到 Browser 主进程模块、可见 webview assets、hidden browser-use webview host、设置与 tab 状态代码。这意味着 IAB 既要呈现用户看得到的页面，也要让自动化 transport 在合适的 renderer context 执行命令。

隐藏宿主不等于“偷偷浏览”。静态产物只能确认它把一部分协议处理、生命周期或后台页面能力从可见视图拆开；具体哪些请求进入哪个 WebView，现有证据没有闭合。组件存在和运行路径是两回事。

IAB 的权限边界不是 Chrome 的权限边界

IAB 页面由 Codex 自己的 Electron/WebView 宿主持有，产品合同并不承诺复用用户默认浏览器的 profile、Cookie 或扩展。现有静态证据也没有闭合 WebView preload 与存储隔离，因此工程上不应假定状态会自动继承；实际边界仍需运行时验证。

07 / 标签页生命周期

标签页生命周期：发现、接管、保留与释放

Browser API 区分 agent 当前 session 创建的 tab、用户已经打开但尚未 claim 的 tab，以及被当前 session 接管的外部 tab。`openTabs()` 返回的是候选快照；`claimTab()` 还会核对 provider tab id、标题和 URL，以在浏览器重启或 id 重用时 fail closed。

`finalize({ keep })` 是一个终态操作：deliverable 表示页面本身是交付结果，handoff 表示用户或后续 turn 还要从当前页面继续。调用后不应再发浏览器命令，因为 session 已经释放或清理其 tab 集合。这个合同把“界面留下什么”从礼貌约定升级成资源所有权语义。

08 / 安全策略

安全策略：来源、动作与用户确认如何叠加

Browser 文档首先把网页、邮件、截图、下载和工具输出定义为不可信内容：它们可以提供事实，却不能授予权限。模型政策再区分需要 action-time confirmation 的发送、提交、购买、上传、删除、登录和浏览器权限动作。到了 client 内部，每个 command 还会经过 `ensureCommandAllowed`，结合当前 URL、backend、site status、guardian 和企业策略判断。

层看见什么主要决定不能替代
模型合同用户意图与动作风险确认、交接或继续站点真实性与 host 权限
Command security命令类型、origin、backend允许、拒绝、询问用户对高风险动作的知情
Site / enterprise远端状态、组织规则站点范围限制页面内 prompt injection 判断
Browser hosttab/session/协议状态是否能实际执行业务意图授权

不能把这一栈笼统写成“全部 fail closed”。大多数未知权限和审批拒绝会阻断命令，但发行包对远端 site-status 不可用保留了记录为 `error_fail_open` 的分支。准确说法是：关键本地身份与命令门禁倾向 fail closed，而某些远端辅助判定为了可用性允许继续并记录异常。

另外，browserAuth 能力有独立 broker socket。它的目标是让凭据流在浏览器与受信 broker 之间完成，而不是把密码或 token 作为普通工具结果回传给模型。静态接口能证明通道和“不回传模型”的合同；具体凭据提供者、存储和远端交换仍需运行时证据。

09 / Chrome 链路

Chrome 链路：扩展、Native Messaging 与 Profile 身份

Browser 与 Chrome 插件的 client bundle 相同；真正的差别出现在接入链。Chrome 路径额外携带 MV3 扩展、固定 extension id、`com.openai.codexextension` Native Messaging host、浏览器 profile 检测与安装诊断。签名 native host 的静态字符串又指向 Native Messaging stdio、app-server / WebSocket 路由和 `/tmp/codex-browser-use`；这些相邻关系支持一条很强的接入链推断，但还不能证明或还原扩展到本地 browser service 的完整逐跳协议。

这也解释了 Chrome 故障为何常常不是“页面点不到”：扩展可能缺失或禁用、选错 profile、Native Messaging manifest 不完整、浏览器未运行、extension instance 已变、用户或扩展中断了控制。把它们全部重试成 Playwright 命令，只会掩盖真正的身份故障。

10 / 结果回传

结果回传：截图、标签页状态与 Response Metadata

client 不只返回方法值。提交代码结束后，它通过 Node REPL hook 汇总最近的副作用命令、当前 URL、open tab ids、截图、WebMCP calls 和 session ended 状态，再写入 Browser Use response metadata。URL 会去掉凭据、query 和 hash，Chrome tab 列表也只保留 origin 级信息。

这个回执层解决两件事。第一，模型下一轮不必完全靠自然语言记住刚才控制的是哪个 tab；第二，产品 UI 可以呈现截图和浏览器状态，而不要求每个工具手工返回重复负载。它也带来一个重要边界：response metadata 是观察辅助，不是副作用的 exactly-once receipt。

下载、文件选择和内容导出又各自穿越额外边界。文件上传需要 backend 支持、浏览器对 `file://` 的权限和用户对敏感文件的确认；下载可以产生临时路径或导出资产，但“拿到路径”不等于文件已被用户验收。

11 / 故障恢复

故障恢复：按失败层选择恢复动作

一个可靠的恢复策略必须先判断失败层。browser binding 断开时，旧 binding 失效；仅 tab 丢失时，应在同一 browser 上重新发现或新建 tab，而不是重置整个 Node session。用户或扩展主动接管时，要停止并自然说明，不能把原始内部错误包装成无限重试。

故障面典型信号正确恢复危险误判
Browser discovery请求后端不存在报告精确后端不可用静默换用另一浏览器身份
Tab ownershipclaim snapshot 不匹配重新列出并由当前状态选择猜测或复用 numeric id
DOM / locator节点、frame、导航已变化重新观察并定位盲重放旧 selector 或坐标
Policycommand blocked / needs consent确认、交接或停止改用低层输入绕过门禁
Extension chainhost、profile 或扩展失联诊断身份链并让用户处理自行安装、修复或切换 profile

页面级漂移是最常见也最容易被低估的故障。DOM snapshot id、locator 结果和 viewport coordinate 都绑定一次观察；导航、响应式布局、iframe 重载和前端 hydration 都会使它们失效。动作成功只说明命令被后端接受，不说明用户目标已经达成。

12 / 结论与边界

结论与边界：这套实现能确认到哪一步

把整条链收回来，Browser Use 不是一个统一的“浏览器点击工具”。同一份可信 client 先在 IAB、Extension 与 CDP 之间确定宿主，再按后端能力暴露 WebMCP、Playwright、DOM-CUA 或坐标 CUA。命令随后经过来源与安全策略检查，进入本地协议或扩展链；动作结束后，截图、标签页状态和 response metadata 才把结果带回模型。

这套分层会直接改变使用和排错方式。IAB 可用，不代表它继承 Chrome 登录态；locator click 成功，不代表旧坐标仍可复用；后端接受命令，也不代表用户目标已经完成。浏览器身份、动作语义和结果验证必须分开判断。

仍然不能确认的部分

现有发行包还回答不了几件事：真实任务中的后端选择与退化顺序；只读 isolated world 对 getter、iframe 和 prototype 技巧的完整抵抗；跨域 OOPIF 中 DOM id 与截图几何如何同步；remote site-status fail-open 的实际范围；WebMCP 页面工具如何绑定 origin、schema 与用户授权。没有运行时 trace 或对应宿主源码，这些都不能写成既定事实。
