这轮核心变化是可选的持久 Node REPL，以及配套的授权和回收机制。DSH 将程序化工具调用称为 PTC。默认仍按次执行；新增能力主要在 alpha 阶段落地，alpha.5 → rc.1 的 355 个文件全部只改版本号。

以下讨论整个 0.2.1 周期。源码与测试源码已核对，未运行 DSH 或模型对照；实现建议与上游行为分开标注。

1. 用 programFormat 生成执行说明

alpha.3 加入 REPL 后，同一份“执行 TypeScript”说明不够用了。alpha.5 按 programFormat 修正 SDK 指令与示例：

执行模式程序形式输出方式
per-call，默认async 函数体；支持顶层 await / returnconsole.log 或 return
persistent-in-memory，可选REPL；支持声明和 await，不支持顶层 returnconsole.log 或最后一个无损 JSON 表达式

自研取舍：让执行器、schema、SDK 示例共用一份能力描述。不要靠固定 Prompt 猜运行时；0.2.0 本就支持函数体和 return，这次是补齐另一种执行形式。

工具入口也收敛了，但 SDK 没退出上下文

移除 both，保留 native / ptc。PTC 模式隐藏被折叠的直接入口，宿主也拒绝直接调用；完整工具类型仍进入 SDK。它不是按需发现工具，TypeScript 注解也不代替宿主参数校验。

2. 持久状态属于 live Agent，不属于聊天 ID

alpha.3 新增 stateOwner：以当前 Agent 对象关联 Kernel，跨调用保留变量、函数和模块；Agent 销毁时 release。无 owner 就建临时环境，同 owner 重叠执行直接拒绝。

  • 普通异常：报错前的修改可能留下。执行 x++; throw Error() 后，x 不会自动回滚。
  • 取消、超时、输出溢出、进程故障：清空环境，下次重建。重启也不会从聊天历史恢复变量。

自研取舍：错误返回要区分“代码失败，状态还在”和“环境失效”。先做好 per-call，再加 owner-scoped 内存；durable checkpoint 是另一项功能。

3. 旧工具引用，走当前一轮的授权

保留的 wrapper 在调用时查询当前 evaluation 的 bindings。新一轮主动调用旧函数可以复用代码；旧一轮遗留的异步回调则以 evaluation has ended 拒绝工具调用。

临时提权时不传 stateOwner，改用独立临时环境，既不继承普通 REPL 的变量，也不把提权环境的变量带回来。可复用数据，不可顺便复用过期授权。

这只约束宿主工具，Node 原生能力另算

模块仍可导入，直接文件访问遵循沙箱策略，初始 process.env 为空；网络和全部系统资源的隔离未验证。原始子进程输出按到达时活跃的 evaluation 归属，因此应等子进程结束，或另加输出路由 ID。

4. 三种结果分开，才谈得上少读中间数据

分层本来就有；alpha.2 补齐的是嵌套 PTC 的 presentationMeta，让子调用也能展示、回放。

  • 脱敏陷阱：只改展示 content，代码仍可能拿到原始 JSON。要限制访问，须拒绝调用或替换 canonical value。
  • 图片例外：成功子调用的最终 content 含图片时，整包附加给模型，包括同包文字；外层报错也可能保留，post-execute 阻断则可替换。

并发不是自动识别“读/写”。isConcurrencySafe(args) === true 才允许 body 有界重叠；缺省、无效值、分类器抛错均独占。前后检查与提交仍有序，出队时重新分类。这是已有机制，代价是可能出现队头阻塞。

5. 沙箱模式切换，多了一道取消屏障

旧版已在程序结束时 abort 并排空嵌套调用。alpha.3 的 PtcCalls 把这套收尾接到 Session 沙箱模式变化上：

取消旧模式调用 → 等待完整调用收尾 → 读取新策略 → 准入新调用

进程层的 PolicyProcesses 同时清理旧策略下的常驻进程，包含闲置的 REPL。否则 UI 已变只读，后台还可能保留旧环境。

自研取舍：别把 abort 当“已经结束”，也别当回滚。对不响应取消的工具设置收尾截止；对已发出的写操作记录未知结果，用幂等键或 readback 恢复。此自动屏障针对沙箱模式，不涵盖任意工具配置变更。

另外四处，值得带回自己的 Harness

动态上下文：在请求准入时刷新

cwd 变成 Session 状态；Agent loop 在 prepareRequest 后、每次尝试发请求前刷新动态 context，不重组整套 tools。请求和工具各取启动时快照，目录变更可追溯；切 cwd 不扩大权限根。

子 Agent：等“仍在推进”，不等所有对象消失

启动统一为 activation；waitForChildren 等推进中的子树，但不被 parked inbox 永久卡住。Headless 用“父级 idle + 子树等待 + Session 序号未变”判定退出；Goal 等完再检查用户输入、暂停与轮次资格，不为纯等待消耗新轮次。

模型接入：容错放在可选层，保留原始历史

超时后不再 await 可能挂死的 iterator.return()；可选扩展失败可降级，核心字段冲突仍拒绝。空 assistant 消息在请求序列化时过滤，不改 Session 原始记录。

插件与存储：区分装上了、跑起来了、收完尾了

alpha.3 支持已安装包替换后的依赖重载；不可替换项保留旧实现、标记待重启，进入替换后失败则不保证回滚。JSONL 存储等消费者 teardown，再关闭监听，接住最后的 turn/end。

兼容与失败边界：四个实现细节
  • 旧 Prompt 仅保护 checkout、Web GUI URL 两段原文，当前值另走动态上下文；不是所有历史 Prompt 不可变。
  • activation 结果在清理尝试、容量归还和通知之后交付，但结果成功不保证 teardown 成功；final flush 为 best effort。
  • HTTP 2xx 后的 accept 异常由 adapter 捕获，SSE 后续仍可能失败。iterator 清理拒绝被吞掉，没有额外日志。
  • appendPluginRecord 将插件状态与模型历史分离，但仅供仓库内 experimental 包，外部插件不应依赖。

自研实现顺序

单次工具桥接 → 明确输出 → 取消与 drain → owner-scoped 内存 → 动态授权与多 Agent 等待。持久 REPL 放在后面：它省下重复计算，也放大每一个生命周期漏洞。
