机制 · Goal Mode

目标不变，每一轮都重新决定下一步

Goal Mode 把“我要完成什么”保存下来。每轮只更新当前进展、剩余条件和下一步动作，直到完成条件真的满足。

同一个真实任务 修复登录接口，并让 14 项测试全部通过
持续目标 登录恢复正常 + 14 / 14 测试通过
Claude Code显式目标状态
本轮读取 目标 + 尚未完成的条件
本轮动作 定位认证入口与失败测试 找到 auth middleware，确认 3 项失败集中在 refresh token。
写回状态 剩余：修复 refresh token
Codex任务生命周期
本轮读取 任务 + 当前工作状态
本轮动作 检查代码与测试反馈 从失败测试回到认证路径，建立下一步修改计划。
推进任务 下一步：修改认证逻辑
第 1 轮结束 两者都没有重新理解整个目标，只更新“现在还差什么”

下一轮会带着同一个完成条件继续，而不是等待用户再次解释任务。

一句话理解Goal Mode 不是“多跑几轮”，而是让目标成为每一轮都能重新读取的控制状态。
真正的差异比较重点不是谁更勤快，而是谁保存了什么状态、如何选择下一步、怎样判断结束。
