这个实验把一次 Agent 请求拆成四类上下文：系统契约、工具 schema、仓库上下文、当前任务。切换不同场景时，可以观察哪些块还能复用，哪些块会导致缓存失效。

<CacheHitDemo client:load />

## 这个实验想表达什么

- 缓存命中依赖稳定前缀，而不是依赖“语义差不多”。
- 工具 schema 和系统规则频繁变化会拖累所有任务。
- 当前任务应该尽量放在较后位置，让前面的稳定块可复用。
- 项目摘要如果能稳定生成，既能提高命中率，也能降低上下文噪声。

后续可以把这个组件改成读取真实请求日志，展示每次构造 prompt 时的缓存块分布。
