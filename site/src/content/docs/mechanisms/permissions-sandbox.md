---
title: 权限与沙箱
description: Agent 自主执行的前提是明确技术边界和交互审批。
---

权限是 Agent 产品能不能进入真实工作流的关键。一个没有权限边界的 Agent 很快会让用户不敢用；一个每步都要用户确认的 Agent 又会失去效率。权限系统的目标不是“阻止 Agent 行动”，而是让低风险行动自动发生，让高风险行动可理解、可审批、可审计。

## 两层模型：能不能做，需不需要问

Codex 文档把 sandbox mode 和 approval policy 分开，这是非常好的抽象。sandbox mode 决定技术上能不能做，例如能否写工作区、能否访问网络、能否读本地路径。approval policy 决定什么时候要问用户，例如越界写入、网络请求、危险命令或副作用工具。

自己的 Agent 也应该采用两层模型：

- 技术边界：进程、容器、文件系统、网络、secret、工具 allowlist。
- 交互审批：用户是否需要确认，审批提示里展示什么信息，审批后如何记录。

如果只有审批没有沙箱，用户批准后 Agent 可能拥有过大权限。如果只有沙箱没有审批，合法但越界的任务无法完成。两者必须组合。

## 沙箱不是一个模式

很多讨论会把沙箱说成一个开关：开沙箱或不开沙箱。真实系统应该有多个 profile：

| Profile | 典型用途 | 权限 |
| --- | --- | --- |
| read-only | 解释代码、审查、规划 | 读工作区，不写文件，不联网 |
| workspace-write | 常规开发 | 读写工作区，保护敏感路径，默认无网络 |
| network-limited | 需要查 docs 或下载依赖 | 指定域名网络访问 |
| cloud-isolated | 托管任务 | 隔离容器、临时凭据、审计日志 |
| danger-full-access | 特殊维护 | 高风险，必须明确授权 |

Claude Code、Codex、OpenCode 都在不同层面提供类似能力。区别在于命名、默认值、用户可见程度和是否有系统级强制。

## 审批提示要具体

坏的审批提示是：“Agent 想运行命令，是否允许？”好的审批提示应该告诉用户：

- 命令或工具是什么。
- 目标路径、URL、repo、issue、账号是什么。
- 可能产生什么副作用。
- 为什么 Agent 需要这样做。
- 如果拒绝，Agent 有什么替代方案。

审批提示越抽象，用户越容易机械点击。Claude Code auto mode 的工程背景就是 approval fatigue：大量低风险请求让用户习惯性批准，安全收益下降。解决方式不是取消所有审批，而是减少低风险审批、提高高风险审批的信息密度。

## 网络权限最容易被低估

文件写入很直观，网络访问更隐蔽。Agent 一旦能联网，就可能下载代码、访问内部服务、发送数据、被网页 prompt injection 影响、触达 metadata 服务、扫描内网或把 secrets 泄露到外部。网络策略不应该只有“开/关”，而应该支持域名 allowlist、私有地址限制、localhost 例外、代理控制和 DNS rebinding 防护。

对开发 Agent 的实践建议：

- 默认关闭命令网络访问。
- 文档查找使用受控搜索或缓存。
- 需要安装依赖时，单独授权 package registry。
- 需要访问 localhost 时，明确目标端口。
- 不允许通配符 `*` 作为长期默认。
- 记录网络请求摘要。

## Secrets 和凭据

Agent 经常需要在有 secrets 的环境工作，但不应该直接看到 secrets。云执行可以把 secrets 用于 setup，然后在 agent phase 移除；本地执行可以通过环境变量 allowlist、MCP server 代理或凭据 broker 暴露最小能力。无论哪种方式，原则都是：Agent 得到能力，不得到原始密钥。

例如 GitHub 操作可以通过 connector 或 CLI token 完成，但模型不应该读取 token 值。数据库查询可以通过受限工具完成，而不是把数据库密码放进 prompt。生产操作可以通过审批过的 runbook 工具完成，而不是让模型直接拼 shell。

## 权限配置也是产品体验

权限配置如果太复杂，用户会放弃；如果太粗糙，用户不敢授权。好的权限界面应该提供预设：只读、自动开发、网络受限、全访问；同时允许高级用户按工具、命令、路径、域名细调。

OpenCode 的 Build/Plan agent 给了一个简单心智模型：Plan 更保守，Build 更能执行。Codex 的 sandbox/approval 提供更细的控制。Claude Code 的 `/permissions` 和 auto mode 则更贴近日常使用。自己的 Agent 可以从预设开始，逐步暴露高级策略。

## 审计和事后解释

权限系统最终要留下审计记录：什么时间、哪个 Agent、在什么上下文下、请求了什么权限、用户是否批准、实际执行了什么、结果是什么。没有审计，权限只是即时交互，不能支持团队信任。

最终回答也应该包含权限相关信息。比如：“我修改了 3 个文件，运行了测试，没有访问网络；没有触碰未提交用户修改。”这样的回答能让用户建立边界感。对高风险操作，最终回答应记录审批和结果。
