---

AgentLab 当前已经有中文电子书雏形：书籍目录、机制篇、四个 Agent 个案、实践篇、实战手册、交互组件和 CI。后续路线图的目标是让它从“内容丰富”继续进化成“内容可生产、事实可保鲜、实验可交互、prompt 可审查”的 Agent 工程实验室。

## v0.1：书稿骨架

状态：已基本完成。

目标：

- 中文文档站。
- 至少覆盖 Claude Code、Codex、Pi、OpenCode。
- 有书籍目录、机制篇、案例篇、实践篇。
- 有缓存演示和 prompt diff 示例组件。
- 有构建和索引生成 CI。

当前版本已经达到这个阶段。

## v0.2：真实数据接入

目标：

- `PromptSnapshot` schema。
- `scripts/build_prompt_diffs.py`。
- `generated/prompt-diffs/`。
- Prompt Diff 组件读取真实 JSON。
- 来源 freshness report。
- docs stats 阈值检查。

这个阶段会让站点从“文档 + 示例组件”变成“文档 + 真实生成数据”。

## v0.3：交互实验扩展

目标：

- 上下文预算可视化。
- 工具风险矩阵。
- 权限审批模拟器。
- Agent loop 回放组件。
- 多 Agent handoff 图。

这些组件应读取结构化数据，而不是把样例写死在 React 组件里。

## v0.4：研究自动化

目标：

- 定时检查官方来源。
- 生成 source freshness report。
- 发现变更后自动开 PR。
- 按 Agent 输出覆盖度报告。
- 自动检查新增章节是否有来源小节。

这个阶段的重点是降低维护成本。

## v1.0：可引用电子书

目标：

- 固定版本标签。
- 稳定 URL。
- 完整来源索引。
- 每章有最后更新时间。
- 每个 Agent 至少有总览、架构、权限、上下文、提示词、工具/扩展、待验证问题。
- 交互组件至少有缓存、prompt diff、权限矩阵、上下文预算。

v1.0 不是停止更新，而是给外部引用一个稳定基线。

## 长期方向

长期来看，AgentLab 可以成为三种东西：

- 个人研究库：记录开发 Agent 的经验和来源。
- 团队手册：指导 Agent 工程实践。
- 实验平台：用可交互组件解释复杂机制。

这三个方向不冲突。关键是保持仓库作为源头，所有内容、数据、脚本和组件都能被版本控制和审查。

衡量路线图是否健康，不只看页面数量。更重要的是每个新增章节是否能追溯来源，是否能转化成清单、脚本、数据或组件，是否让下一次更新更容易。AgentLab 的长期价值来自持续维护能力：内容越丰富，越需要统计、校验、来源保鲜和自动化审查共同约束。
