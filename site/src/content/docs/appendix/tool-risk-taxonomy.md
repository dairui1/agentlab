---
title: 工具风险分类
description: 按副作用、数据访问和可撤销性为 Agent 工具建立风险等级。
---

工具风险分类是权限系统的基础。如果所有工具都用同一种审批方式，用户会疲劳，系统也无法自动判断。风险分类不是为了阻止工具，而是为了让低风险工具自动运行，高风险工具可解释地停下来。

## 等级 0：纯观察

示例：列目录、读取公开文档、查看 git status、读取当前工作区非敏感文件。

默认策略：允许。记录必要日志。返回内容如果来自外部或用户输入，仍要标记不可信。

## 等级 1：低风险本地操作

示例：运行测试、运行 lint、生成临时缓存、读取 LSP diagnostics。

默认策略：允许或轻量提示。需要超时、工作目录和输出截断。注意测试可能产生缓存或改写 snapshot。

## 等级 2：工作区写入

示例：修改源码、格式化文件、更新 lockfile、生成文档。

默认策略：允许或询问，取决于模式。必须生成 diff，保护用户已有修改，不写敏感路径。

## 等级 3：网络访问

示例：访问官方文档、下载依赖、调用 API、访问 localhost。

默认策略：默认关闭或按域名 allowlist。网络访问引入数据外传和 prompt injection 风险，应记录目标域名和用途。

## 等级 4：远端副作用

示例：发 GitHub 评论、开 PR、push 分支、发 Slack 消息、提交表单。

默认策略：询问用户。审批提示必须显示目标资源和发送内容。对于可编辑草稿，优先草稿模式。

## 等级 5：高风险不可逆操作

示例：删除生产数据、修改权限、旋转密钥、支付、发送不可撤回消息、读 secrets。

默认策略：拒绝或强审批。普通 Agent 不应直接执行。应通过专门 runbook、人工审批和审计系统处理。

## 复合风险

工具风险不是固定值。读取文件通常低风险，但读取 `.env` 就高风险。网络访问公开文档较低风险，访问内网 metadata 服务高风险。发送消息如果是草稿低风险，直接发送给客户高风险。

因此风险判断应考虑：

- 工具类型。
- 目标资源。
- 参数内容。
- 当前环境。
- 用户授权。
- 是否可撤销。
- 是否包含敏感数据。

## 风险分类的产物

每个 Agent 项目都应维护一张工具风险表：

| 工具 | 风险等级 | 默认策略 | 审计字段 | 回归测试 |
| --- | --- | --- | --- | --- |
| read_file | 0-5 by path | allow/deny | path | secret path blocked |
| shell | 1-5 by command | ask | cmd, cwd | dangerous command blocked |
| github_comment | 4 | ask | repo, pr, body | approval required |

这张表应该比 prompt 更权威。
