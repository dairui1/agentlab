---
title: 提示词分类
description: Agent 提示词应按角色、工具、权限、上下文、输出和安全等维度分类管理。
---

提示词分类的目的不是学术命名，而是让 prompt 变更可审查。一个系统提示词可能同时包含角色、风格、工具规则、权限边界和最终回答格式。如果没有分类，diff 只能看到文本变化，看不出行为影响。

## 身份与角色

定义 Agent 是什么。例如编码助手、研究助理、个人陪伴者、审查员、自动化 worker。身份会影响语气和行动边界。Pi 的 persona 和 Claude/Codex 的 coding-agent persona 属于不同类型。

变更风险：身份变化可能影响所有回答风格和用户预期。

## 任务边界

定义 Agent 做什么、不做什么。例如“帮助修改代码库”“不替代专业医疗建议”“不直接发布未经审查内容”。任务边界是安全和产品定位的基础。

变更风险：边界扩大可能带来新副作用；边界收窄可能降低可用性。

## 工具规则

定义什么时候用工具，如何选择工具，工具失败怎么办，是否需要验证。编码 Agent 的大量行为来自工具规则。工具规则变化会直接影响轨迹。

变更风险：工具使用更积极可能提高效率，也可能增加错误副作用。

## 权限边界

定义哪些动作允许、询问、拒绝。例如文件写入、网络访问、远端修改、发送消息、读取 secrets。权限边界应同时存在于 prompt 和系统配置中。

变更风险：权限放宽是高风险变更；权限收紧可能导致任务失败或更多审批。

## 上下文优先级

定义系统指令、项目规则、用户最新消息、工具输出、外部网页、记忆之间的优先关系。不可信内容不能覆盖高优先级指令。

变更风险：优先级变化可能导致 prompt injection 防护失效或项目规则被忽略。

## 输出契约

定义最终回答和中间更新如何写。例如是否列文件、是否报告验证、是否说明风险、是否给下一步。输出契约影响用户信任。

变更风险：过短会丢失风险；过长会降低效率。

## 失败恢复

定义遇到错误、权限不足、测试失败、来源缺失、工具超时时如何处理。Agent 的可靠性很大程度取决于失败恢复，而不是 happy path。

变更风险：重试过多会浪费资源；过早放弃会降低完成率。

## 安全与拒绝

定义如何处理恶意请求、危险操作、隐私、危机和不可信内容。关系型 Agent 和编码 Agent 都需要安全层，但触发场景不同。

变更风险：安全规则放松可能造成真实伤害；过度拒绝会影响正常工作。

## 版本记录模板

每次 prompt 变更可以按这个模板记录：

- 变更类别。
- 变更前行为。
- 变更后行为。
- 预期收益。
- 可能副作用。
- 验证样例。
- 回滚条件。

这样 prompt diff 才能进入工程评审。
