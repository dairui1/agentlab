Pi 的核心价值不在“能调用多少工具”，而在关系型体验。它代表了一类与编码 Agent 很不同的产品：用户不是把一个明确开发任务交给它，而是与一个有稳定语气、人格和情绪承接能力的助手对话。研究 Pi，可以避免我们把所有 Agent 都理解成“会执行工具的工程师”。

## 任务上下文和关系上下文

编码 Agent 的上下文主要围绕任务：仓库、文件、diff、命令、测试、issue、PR。Pi 这类助手的上下文主要围绕关系：用户是谁、用户当前状态如何、之前聊过什么、助手用什么语气回应、什么内容需要边界。

关系上下文不是简单历史聊天记录。它包含更细的层：

- 当前情绪：焦虑、兴奋、困惑、低落、愤怒。
- 长期偏好：用户喜欢直接建议，还是喜欢先被倾听。
- 关系节奏：这是一轮快速问答，还是长期陪伴。
- 风险信号：自伤、危机、医疗、法律、财务、被操控风险。
- 人格一致性：助手是否保持稳定风格。
- 记忆边界：哪些内容不应长期保存。

这些上下文很难用传统 RAG 解决。RAG 擅长找资料，但关系型 Agent 还要判断“这段历史是否应该被提起”。有些信息虽然相关，但直接提起会让用户不舒服；有些信息虽然旧，但对长期陪伴很重要。

## Backstory 和 persona

Inflection 的开发者文档中，Pi 模型被描述为包含 backstory、emotional intelligence、productivity 和 safety。Backstory 不是普通文案，它会影响助手如何解释自己、如何保持人格一致、如何在不同场景下回应。

一个关系型 Agent 的 persona 至少要回答：

- 它是谁，是什么，不是什么。
- 它和用户是什么关系。
- 它如何表达关心。
- 它如何处理不知道的问题。
- 它是否会主动建议行动。
- 它如何保持边界。

Persona 不是“说话温柔”这么简单。温柔但无边界可能很危险；直接但无同理心会破坏关系；过度拟人可能让用户误判系统能力。Pi 的研究价值正在于它把 EQ 放在产品中心。

## 记忆和 consent

关系型 Agent 的记忆比编码 Agent 更敏感。编码 Agent 记住“这个项目用 pnpm”通常低风险；关系型 Agent 记住“用户最近和家人冲突”就涉及隐私和心理安全。用户应该知道哪些内容会被记住、为什么记住、如何删除。

记忆可以分成三类：

- 会话内短期状态：当前对话需要，但不跨会话保存。
- 用户明确同意的长期偏好：称呼、沟通风格、目标。
- 高敏感信息：健康、家庭、财务、身份、创伤，应默认不长期保存或需强 consent。

如果 Agent 无法清楚解释记忆策略，它就不应该积极记忆高敏感内容。

## 安全边界是关系的一部分

关系型 Agent 不能只追求“用户觉得被理解”。有时真正的支持是设边界：不做诊断、不替代专业帮助、不鼓励危险行为、不操控用户情绪、不承诺现实世界能力。

安全边界可以写成产品规则，但要体现在语气中。用户情绪低落时，机械拒绝会伤害体验；无边界安慰又可能延误帮助。好的关系型 Agent 需要同时做到：承接情绪、说明边界、给出安全下一步。

## 对编码 Agent 的反向启发

Pi 也能反向启发编码 Agent。编码 Agent 虽然不做情绪陪伴，但也需要关系感：尊重用户已有工作、不夸大结果、承认不确定、解释风险、避免把用户当成命令输入器。一个工程 Agent 的信任关系同样需要长期积累。

例如最终回答不要只写“完成了”，而要写清楚：改了什么、验证了什么、没验证什么、下一步风险是什么。这种透明度就是工程场景中的“关系安全”。
