title: Pi 工具调用设计
description: 当关系型 Agent 开始支持 tool calling，确认、情绪状态、隐私和现实副作用如何共同影响设计。
---

Inflection-3 Pi 文档提到 Pi 3.1 Preview 包含 tool calling，并处于 agentic workflows 和 advanced features 的 beta testing。这个信息很重要：关系型助手也会走向可行动 Agent。但关系型 Agent 的工具调用不能照搬编码 Agent 的做法，因为用户状态和信任关系会影响授权质量。

## 情绪状态影响授权

编码 Agent 询问“是否运行测试”时，用户通常能理性判断。关系型 Agent 如果在用户情绪激动、焦虑或脆弱时请求授权，情况不同。用户可能希望助手立刻代替自己行动，例如发消息、取消订单、提交表单、联系他人。此时“用户点击确认”未必代表充分知情。

因此关系型 Agent 的高风险工具调用需要更强确认：

- 显示将要发送或执行的具体内容。
- 给用户修改机会。
- 高情绪场景建议延迟或草稿模式。
- 不把情绪支持和行动确认混在一句话里。
- 对不可撤销操作保持强审批。

## 工具分类

关系型 Agent 的工具可以分成几类：

| 类型 | 示例 | 风险 |
| --- | --- | --- |
| 信息型 | 查天气、查日程、查公开资料 | 低到中 |
| 组织型 | 整理待办、生成计划、写草稿 | 中 |
| 沟通型 | 发邮件、发消息、预约 | 中到高 |
| 财务/医疗/法律 | 支付、保险、病历、合同 | 高 |
| 记忆型 | 保存偏好、删除记忆 | 中到高 |

不同类型需要不同确认。沟通型工具尤其敏感，因为它会代表用户与他人互动。

## 草稿优先

关系型 Agent 的默认策略应是草稿优先。用户要求“帮我回复他”时，助手先生成草稿，而不是直接发送。用户确认内容、收件人、语气和时间后，才考虑发送。

草稿优先有几个好处：

- 给用户重新思考空间。
- 降低情绪冲动行动。
- 让助手建议和用户意图分开。
- 保留用户控制权。

这和编码 Agent 的“小步 patch + diff 审查”很像，只是对象从代码变成现实沟通。

## 记忆工具

关系型 Agent 的“记住这件事”也是一种工具调用。它会改变未来对话，因此应有可见确认。比如用户说“以后提醒我我不喜欢开会”，可以保存偏好；用户说“我今天很难过”，不应自动永久保存。

记忆工具应支持：

- 保存。
- 查看。
- 修改。
- 删除。
- 临时记住。
- 不要记住。

没有这些控制，记忆会变成隐性副作用。

## 安全升级路径

当用户表达危机、伤害、违法或高风险决策时，工具调用应降级。助手可以提供支持性语言、建议联系现实帮助、生成安全计划，但不应执行可能加剧风险的动作。

这类场景中，Agent 的目标不是完成用户请求，而是保护用户安全。关系型 Agent 的工具系统必须理解这一点。

## 对编码 Agent 的启发

编码 Agent 也可以学习草稿优先。高风险代码变更先生成 plan 或 patch，不直接 apply；生产命令先生成 runbook，不直接执行；远端操作先展示 payload，不直接发送。Pi 方向的工具调用设计提醒我们：用户授权质量与上下文状态有关。
