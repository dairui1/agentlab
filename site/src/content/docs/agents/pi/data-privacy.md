---
title: Pi 数据与隐私
description: 关系型 Agent 中训练数据、对话数据、记忆、隐私和用户信任如何影响产品设计。
---

Pi 的数据与隐私问题比编码 Agent 更敏感。编码 Agent 主要处理代码、文件、命令和开发上下文；Pi 这类关系型助手会处理个人情绪、生活经历、偏好、困扰和长期对话。用户越信任它，越可能分享敏感信息。因此数据策略不是合规附录，而是产品核心。

## 训练数据透明度的价值

Inflection 公开了训练数据透明度声明，说明训练数据可能包括公开数据、授权数据和合成/蒸馏数据，并提到去重、质量过滤、数据混合、内容过滤和格式标准化等处理。这些信息不能告诉我们 Pi 的完整内部机制，但能说明关系型 Agent 的数据治理需要公开沟通。

用户与关系型助手互动时，会关心几个问题：

- 我的对话是否被保存？
- 是否用于训练？
- 是否能删除？
- 是否会被人工查看？
- 是否会影响未来回答？
- 敏感信息如何处理？

如果产品无法回答这些问题，长期信任会很脆弱。

## 对话数据和训练数据不同

不要把训练数据和用户对话数据混为一谈。训练数据是模型能力的来源；用户对话数据是产品使用过程中的个人信息。一个产品可以使用公开/授权数据训练模型，但仍需要单独说明用户对话如何保存和使用。

关系型 Agent 的对话数据还包括隐含信息：情绪状态、家庭关系、健康担忧、工作压力、价值观和习惯。这些信息即使没有身份证号，也可能高度敏感。

## 记忆最小化

关系型 Agent 不应该默认记住所有内容。记忆最小化原则是：

- 当前对话需要的信息，优先留在 session 内。
- 长期偏好需要用户可见。
- 敏感内容默认不长期保存。
- 用户可以查看、修改、删除记忆。
- 记忆应有来源和时间。

例如“用户喜欢简洁回答”可以长期保存；“用户上周谈到家庭冲突”就应更谨慎，除非用户明确希望未来继续跟进。

## 情绪智能和隐私的张力

情绪智能需要上下文。助手要理解用户状态，就需要读取或推断情绪线索。但推断越多，隐私风险越高。一个过度推断的 Agent 可能让用户感觉被监控；一个完全不记得上下文的 Agent 又会显得冷漠。

可行的中间路线是透明控制：

- 明确告诉用户哪些内容会被用于个性化。
- 对敏感推断保持保守。
- 避免在没有必要时主动提及旧敏感内容。
- 让用户能关闭记忆。
- 在高风险场景中优先安全，而不是个性化。

## 日志和评测

关系型 Agent 的日志也要谨慎。开发团队需要评测产品质量，但不能把用户敏感对话随意进入评测集。建议：

- 日志脱敏。
- 高敏感内容过滤。
- 人工审查最小化。
- 评测样例使用合成数据或明确授权数据。
- 对安全事件保留必要审计，但限制访问。

Pi 这种产品方向提醒我们：Agent 评测和数据治理必须一起设计。

## 对 AgentLab 的边界

AgentLab 研究 Pi 时，不应尝试保存个人对话或推断消费者产品内部记忆。可以研究公开开发者文档、公开公司说明、训练透明度声明和产品定位。对消费者端记忆、危机协议、内部 prompt 这类没有公开来源的信息，应保持待验证。
