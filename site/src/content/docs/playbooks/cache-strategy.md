title: 缓存策略
description: 设计 prompt cache、工具结果缓存和上下文摘要缓存时，应该稳定什么、刷新什么、审查什么。
---

缓存是 Agent 成本和速度优化的重要手段，但它也是架构问题。缓存不是简单把请求结果存起来，而是决定哪些内容应该稳定、哪些内容应该刷新、哪些内容变化会影响行为。

## 三类缓存

Agent 系统常见三类缓存：

1. Prompt cache：稳定前缀复用，降低模型成本和延迟。
2. 工具结果缓存：避免重复读取相同 URL、文档、仓库信息。
3. 摘要缓存：把长文件、长日志、长会话压缩成可复用摘要。

三类缓存风险不同。Prompt cache 主要关注顺序稳定；工具结果缓存关注 freshness；摘要缓存关注信息丢失和来源。

## Prompt cache 策略

稳定前缀应包括：

- 系统角色和安全边界。
- 工具 schema。
- 项目规则摘要。
- 高层工作流。

不应放在稳定前缀中间的内容：

- 当前用户任务。
- 最新命令输出。
- 随机排序搜索结果。
- 时间戳。
- 临时计划。

如果需要加入时间或动态信息，尽量放在后缀。

## 工具结果缓存

工具结果缓存要记录来源和过期策略。比如官方文档可以缓存一天，GitHub PR diff 应按 commit sha 缓存，网页搜索结果可能需要更短时间，本地文件读取应按 mtime 或 git hash 判断。

缓存 key 应包含：

- 工具名。
- 参数。
- 来源 URL/path。
- 版本信息或 commit。
- 权限上下文。

不要让一个用户或项目的私有缓存被另一个上下文复用。

## 摘要缓存

摘要缓存最危险，因为它会变成“看起来像事实”的二手信息。每个摘要应保留：

- 原始来源。
- 生成时间。
- 适用范围。
- 摘要模型/版本。
- 未覆盖内容。
- 置信度。

对于高风险修改，Agent 应重新读取原文，而不是只信摘要。

## 缓存失效

缓存失效不是异常，而是系统设计的一部分。常见失效条件：

- 文件内容变了。
- 工具 schema 变了。
- 系统 prompt 变了。
- 权限策略变了。
- 来源页面更新。
- 用户切换项目或账号。
- 模型版本变化。

失效条件应该被显式记录。否则用户会遇到“为什么 Agent 还在用旧信息”的问题。

## 可视化

AgentLab 现有缓存命中演示只是心智模型。后续可以接真实数据：

- 每次请求的前缀块。
- 每块 token 数。
- 是否命中缓存。
- 失效原因。
- 成本估计。

这样缓存从隐藏优化变成可解释工程指标。
