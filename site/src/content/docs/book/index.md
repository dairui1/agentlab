这本手册的目标不是给 Agent 下一个漂亮定义，而是把开发、调试、维护 Agent 时真正会反复遇到的问题写清楚。一个可用的 Agent 产品往往不是“模型能力强”这么简单：它还需要稳定的工具协议、可解释的权限边界、能复用的上下文策略、可审查的提示词版本、可回放的操作日志、能被团队接受的安全默认值，以及持续更新内容和实验的发布机制。

AgentLab 的内容会以中文为主。代码、配置字段、命令、协议名和文件名保留英文，因为这些是工程接口。站点采用文档站形态，但在关键概念旁嵌入交互组件，例如缓存命中演示、提示词版本 diff、工具权限矩阵、上下文预算可视化和 agent loop 回放。最终形态应该像一本持续更新的电子书，也像一个可以运行实验的工程实验室。

## 本书主线

第一条主线是“机制”。我们把 Agent 拆成可讨论的层：用户意图、系统提示词、长期项目规则、上下文构造、模型推理、工具调用、权限决策、执行环境、观察结果、状态压缩、最终交付。每一层都可能出问题，也都可以被工程化。提示词不是魔法文案，而是一个有版本、有测试、有 diff、有回滚策略的接口。工具不是随手暴露的函数，而是影响安全、成本、速度和可预测性的协议。上下文不是越多越好，而是需要根据任务、风险和缓存策略做选择。

第二条主线是“案例”。Claude Code、Codex、Pi、OpenCode 代表了四种不同的 Agent 产品方向。Claude Code 和 Codex 都是强工程化的编码 Agent，但它们在权限、沙箱、定制层、产品表面和生态扩展上有不同设计。Pi 不是编码 Agent，它更像关系型、情绪智能、个人助理方向的样本，能帮助我们理解长期对话、人格一致性和安全边界如何影响 Agent。OpenCode 则提供了开源编码 Agent 的可检查样本，适合从仓库结构、配置、权限、模型 provider 和插件体系中学习。

第三条主线是“生产”。这本书本身也应该被 AgentLab 项目生产出来：公开来源定时检查，结构化数据生成，prompt snapshot 生成 diff，站点 build 通过 CI，低风险内容自动更新，高风险内容走 PR 审核。文档不是静态物，而是 Agent 研究和开发流水线的输出。

## 读者假设

这本书假设读者不是第一次使用 LLM，但可能正在从“调用一个模型”走向“开发一个 Agent”。如果你正在做以下事情，这本书应该有用：

- 给模型接 shell、文件系统、浏览器、GitHub、数据库或内部系统。
- 设计工具权限、沙箱、审批、审计、回滚和日志。
- 想知道系统提示词、项目规则、用户消息、记忆和工具结果怎么组织。
- 想比较 Claude Code、Codex、OpenCode 这些编码 Agent 的产品机制。
- 想理解 Pi 这类关系型助手为什么不应该用编码 Agent 的标准去评价。
- 想把自己的研究资料、prompt 版本和实验组件长期维护起来。

## 写作原则

本书会持续区分三种内容。第一类是“来源事实”，来自官方文档、公开仓库、公开博客、开发者文档或项目内可复现脚本。第二类是“工程观察”，来自产品行为、使用体验、开源实现或对比分析。第三类是“设计建议”，是 AgentLab 对开发 Agent 的判断。任何没有直接来源的判断都应该被标注为观察、推断或待验证，而不是假装成事实。

这里不会收集未授权泄露的私有提示词，也不会把账号 token、私有工作区内容或非公开系统提示词放进仓库。提示词研究只处理公开、可引用、用户自有或明确允许保存的材料。对于 prompt diff，优先记录结构、类别、版本变更和影响，而不是追求复制完整文本。

## 当前完成度

当前版本是第一批书稿，不是完成稿。它已经把站点从短文档扩展成书籍结构，并覆盖四个指定 Agent。后续需要继续扩写每个机制章节、把真实 prompt snapshot 接入 diff 组件、补充更细的工具矩阵、加入上下文预算可视化，并把公开来源检查做成定时任务。

你可以从 [阅读路线](/agentlab/book/reading-guide/) 开始，也可以直接进入 [四个 Agent 对比矩阵](/agentlab/comparison/matrix/)。
