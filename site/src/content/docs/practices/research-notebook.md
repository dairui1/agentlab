---
title: 建立 Agent 研究笔记
description: 如何把公开来源、观察、推断和待验证问题组织成可持续更新的 Agent 研究库。
---

Agent 研究最容易变成碎片收藏：看到一篇博客、截一段 prompt、记一个产品功能、存一个 GitHub issue。短期看很快，长期会失去来源、版本和上下文。AgentLab 的目标是把研究笔记组织成可持续更新的知识库。

## 四层笔记法

建议把研究内容分成四层：

1. 来源层：URL、仓库、commit、发布时间、访问时间、作者。
2. 摘录层：来源中直接支持的事实，尽量短，不大段复制。
3. 分析层：你对事实的工程解释、对比和推断。
4. 行动层：后续要验证、要写进文档、要做成组件或脚本的任务。

很多笔记的问题是把这四层混在一起。比如“Claude Code 支持 hooks，所以我们应该用 hooks 做安全拦截”里面前半句是来源事实，后半句是设计建议。分层后，未来来源变化时更容易更新。

## Evidence level

每条结论都应标注 evidence level：

- `source`: 官方文档、公开仓库、公开博客直接支持。
- `observed`: 自己重复使用或实验观察到。
- `inferred`: 基于多个事实推导，但没有直接文档。
- `todo`: 还没有验证。

这个标记能防止文档越来越像传言。尤其是提示词、权限默认值、功能可用性、模型名、价格这些易变信息，必须有来源或保持待验证。

## 研究页模板

每个 Agent 研究页可以固定包含：

- 产品定位。
- 使用表面。
- Agent loop。
- 工具模型。
- 权限模型。
- 上下文和记忆。
- 扩展机制。
- 提示词研究方向。
- 与其他 Agent 的差异。
- 待验证问题。
- 来源。

固定模板的好处是方便比较。否则每个 Agent 页都会按不同结构写，后续很难生成矩阵。

## 来源更新

Agent 产品变化很快。研究笔记应该记录访问日期和易变字段。比如 OpenCode docs 近期频繁更新，providers 数量、agents 列表、权限规则可能变化；Codex manual 会更新功能成熟度和配置；Claude Code 的 hooks、skills、subagents 也可能迭代；Pi 的开发者模型和消费者产品可能不同步。

来源更新可以先不自动改正文，而是生成 freshness report：

- 哪些 URL hash 变化。
- 哪些页面标题或 headings 变化。
- 哪些关键词出现或消失。
- 哪些 Agent 页面引用了该来源。

人再决定是否更新正文。

## 不要收集不该收集的东西

Agent 研究很容易被“系统提示词泄露”吸引。AgentLab 的原则是：不保存未授权私有 prompt，不保存账号密钥，不保存内部工作区内容，不保存无法引用的泄露材料。研究 prompt 的价值不在复制秘密文本，而在理解结构：工具、权限、上下文、风格、验证、拒绝、最终回答。

如果你有用户自有或公开合法 snapshot，也要记录范围和处理方式。必要时只保存 diff 类别和摘要，而不是全文。

## 从笔记到站点

研究笔记进入对外站点前，应经过三步：

1. 来源检查：是否可引用，是否足够新。
2. 事实/推断分离：哪些是来源事实，哪些是分析。
3. 结构化提炼：是否能进入矩阵、组件或生成脚本。

这样站点才不会只是草稿集合，而会成为经过整理的工程手册。
